## Plan Summary

Wire the V1 non-mutating Bernie tool-intent route (POST /appointments/proposals/bernie/tool-intent, extend-only) into the Diary "Ask Bernie" flow. A conservative deterministic router sends explicit appointment-extension intents that already have a resolvable visible-diary appointment context to the tool-intent route, maps the typed BernieToolIntentOut into the existing Bernie session/render machinery, and gates the confirm affordance so it only appears when backend proposal evidence (result=proposal_ready and proposal.safe) is present. Claude owns the routing/contract/typed-response/confirm-evidence seam plus focused backend and deterministic diary contract tests; Antigravity owns the visible friendly copy/CSS/card layout; Codex owns the invariants packet.

## My Understanding

V1 (commit f1c88e4) shipped POST /appointments/proposals/bernie/tool-intent: a non-mutating route that supports only appointment extension, deterministically parses extend/lengthen plus a target duration from the instruction, resolves exactly one matching appointment from visible-diary context_frames, delegates to propose_update_appointment, and returns typed BernieToolIntentOut {intent, safe, result(proposal_ready|clarification_required|blocked|unsupported), tool_intent, autonomy_tier, requires_confirmation, summary, proposal(AppointmentUpdateProposalOut|null), warnings, blocks, source_attribution}. It never writes; write authority stays staff_confirmed_put_only. V1 also added appointment_id to diary context frames (buildBernieContextFrames). BUT nothing in the Diary calls the route yet: the Ask Bernie button (btn-bernie-instruction-submit in renderBernieInstructionInput, diary.js ~5405) always POSTs to /appointments/proposals/bernie/interpret-booking-instruction (the booking flow). Confirming an extension needs no new endpoint: BernieToolIntentOut.proposal.command is an AppointmentUpdateCommand carrying appointment_id plus duration_minutes, so confirm reuses the existing update-confirm pattern (PUT /appointments/{id} with the command payload, mirroring the resize/edit path at diary.js ~7414 propose then ~7452 PUT). Invariants to preserve: model/advisory text can never write or bypass proposal/confirm; no confirm control may render without backend proposal evidence; the frontend router is only a conservative optimization and the backend gate remains the authority (under-routing falls back to today booking flow with no regression).

## Implementation Steps

1) Add classifyBernieToolIntent(text, context): returns {route: tool-intent|booking, tool_intent, appointment_id} only when text matches a conservative extend/lengthen pattern (kept in lockstep with the backend extend/lengthen gate — record as a cross-file invariant) AND a single diary appointment context is resolvable; otherwise route=booking. 2) In the Ask Bernie submit handler (~5405), branch: if route==tool-intent call submitBernieToolIntent instead of the interpret-booking POST, preserving the existing session event/turn bookkeeping and the Asking button state. 3) submitBernieToolIntent POSTs {instruction, reference_date, context_frames: buildBernieContextFrames({})} to /appointments/proposals/bernie/tool-intent and parses BernieToolIntentOut. 4) applyBernieToolIntentResponse maps the typed result into the Bernie session/render path: proposal_ready renders summary plus proposal plus confirm control; clarification_required/blocked/unsupported render summary plus blocks with NO confirm control; always surface warnings; store proposal.command for confirm. 5) confirmBernieToolIntentExtension PUTs /appointments/{proposal.command.appointment_id} with the command payload (reusing the existing update-confirm pattern), guarded so it can only run when result==proposal_ready AND proposal.safe; on success loadDiary(true) plus scrollToAppointment. 6) Emit stable data-testid hooks (bernie-tool-intent-summary, bernie-tool-intent-proposal, btn-bernie-tool-intent-confirm) with minimal placeholder copy for Antigravity to style/word. 7) Backend contract tests in tests/test_bernie_tool_intent.py. 8) Smoke fixture plus route stub plus checks_diary.json rows for the routing/confirm-evidence contract. 9) Bump diary.js ?v=N once. 10) Run verification (py_compile, node --check, focused pytest, diary smoke, frontend version check).
