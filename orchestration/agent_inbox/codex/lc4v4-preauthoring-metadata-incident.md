# LC4V4 Pre-Authoring Metadata-Only Boundary Incident

Date: 2026-07-15

Status: the first LC4V4 content phase is stopped before authorship, sealing, or
evaluation. A new explicit Yuri decision is required before a fresh attempt.

## What happened

After the accepted pre-content checkpoint `1c0e3ba3`, Sol ran a broad `rg`
search to locate the public `ReceptionScenarioSpec` definition and ordinary
public construction examples. The command included negative globs intended to
exclude v1-v3 material, but Windows path matching did not exclude every
backslash-form path. Terminal output therefore displayed the filename of one
v3 content-blind framework test.

No protected file was opened. No v1-v3 fixture, support implementation,
authoring program, manifest, seal, receipt, report, test content, scenario ID,
utterance, expected label, source span, hash, aggregate result, or case-level
surface was read, run, regenerated, evaluated, or used for tuning. No actual
v4 authoring program, corpus, manifest, quality receipt, seal, consumed seal,
or result existed.

## Mechanical consequence

The frozen one-shot rule deliberately makes evidence invalid if a protected
v1-v3 surface is enumerated after the rule is frozen. A protected test filename
is metadata, but it is still enumeration. Sol therefore stops rather than
reinterpret the rule after observing the incident. The accepted content-blind
framework remains valid; this prospective content attempt does not.

## Recommended recovery

Authorize a fresh v4 content attempt from the already accepted framework, with
all content-phase reads restricted to an explicit allowlist of named public v4
modules and the public scenario schema. Broad recursive search and globbing
must be prohibited until the new attempt is consumed. Re-freeze the same
thresholds under a new acceptance-rule identity, then author a genuinely fresh
corpus without using the displayed filename or any v1-v3 material.

This recommendation does not authorize a retry by itself.
