Reuse the authored-synthetic page fixture and route harness from
`review.test_reception_one_selected_action_console`; do not duplicate its full
server or intercept implementation.

The new module must directly prove:

1. selecting time, entering `09:15`, switching to duration and choosing `45`,
   then switching to practitioner and choosing the existing active target keeps
   all three values when each field view is revisited;
2. those same-family switches issue zero proposal, confirm, raw or unexpected
   mutation routes and show a visibly provisional shared-draft summary naming
   the changed dimensions;
3. collapse discards the whole update draft, and crossing to status also
   discards it without adding status to any update payload;
4. from a fresh draft, the three edits followed by the visible update Review
   control issue exactly one proposal body with start `09:15`, duration `45`
   and the target practitioner, while confirm count remains zero and the
   existing dialog is visible even in fixture mode `safe`;
5. only clicking visible `Confirm & Save` produces exactly one confirm, zero
   raw/unexpected mutations and one freshly reconciled truth summary containing
   `9:15`, `45` and the target practitioner display;
6. Escape from that safe dialog produces zero confirms, current truth remains
   unchanged and focus returns to the active update field;
7. four native buttons, exactly one expanded value, one mounted editor, one
   polite atomic live region and no horizontal overflow remain at desktop,
   tablet and phone widths; and
8. a source guard identifies one combined bridge entry and rejects sequential
   proposal loops, raw `PUT`/`PATCH`, status in the combined input and any new
   proposal/confirm route spelling.
