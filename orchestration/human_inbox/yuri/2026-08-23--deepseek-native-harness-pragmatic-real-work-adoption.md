# DeepSeek native Harness pragmatic real-work adoption

Date: 2026-08-23

Timestamp: 2026-08-23T12:36:36.1771905+10:00 (Australia/Brisbane)

## Lay summary

The native Harness is worth using now, but not because it has already proved
that DeepSeek writes better code inside it. Its demonstrated advantage is that
we can tell where a run stopped and what it did. The first real-work attempt
never reached DeepSeek: the off-the-shelf runner offered seven tools and our
broker correctly allowed only three.

We were making adoption unnecessarily difficult by insisting that every new
task fit an old synthetic runner without any adaptation. Going forward we will
allow one small reusable adjustment as part of the first real job, then let
DeepSeek do useful multi-step work. We will not open another preliminary
Harness-testing programme.

The clockwork will take three readings—before work, at the terminal, and after
acceptance or recovery—rather than trying to synchronize every internal model
step. The strict broker and evidence trail stay in place.

The first selected opportunity is the next default-off check-in admission-input
tranche. DeepSeek will contribute a bounded source/test candidate; Sol retains
the product decision, testing, integration and acceptance.
