# Governance clockwork ergonomics and efficacy review

Date: 2026-08-23

Timestamp: 2026-08-23T15:54:57.4111487+10:00 (Australia/Brisbane)

Result: `safety_strong_operator_interface_overweight_narrow_repair_justified`

## Lay conclusion

Yes, the clockwork has taught us something valuable during the long attempt to
mesh it with the DeepSeek Harness. Its safety mechanics are working: mistakes
were stopped, state could be restored exactly, and neither product nor
protected surfaces were affected. Its controls also made the native Harness's
failures far more attributable than the retained Claude Code failures.

But the operator interface is carrying too much clerical work. The last two
closeout forms contain 73,459 bytes, 1,173 lines and 785 individual scalar
entries. In the latest packet, finishing the closeout took about as long as
producing and testing the product evidence. Three rollbacks were caused by
facts the repository could have checked or counted itself.

The best next move is not to loosen the clock. It is to make the existing tick
read the whole prospective state before it moves the pointer, report every
problem together, and own its own transaction counters. That directly removes
the latest three rollback sequences without adding a field, document or
approval gate.

## What the DeepSeek gear work established

The gear work was not wasted. It established the useful boundary between the
systems: `prepared`, `terminal`, and `accepted_or_recovered`. That is enough for
the clockwork to know when the Harness has custody, what terminal occurred and
whether Sol accepted or recovered the work. Per-turn and per-subcoordinate
clockwork coupling was correctly retired.

The native Harness improved traceability, not useful completion. The first
pragmatic real task was rejected before provider I/O because its visible stock
tool set exceeded the broker contract. The later occupied development attempt
made one provider request and one edit call but produced no candidate. Both
failures were attributable and cleanly terminated. That supports keeping the
specific native profile paused; it does not justify a silent Claude fallback
or a comparative reliability rate.

There is also a governance-text inconsistency worth removing later: the live
operation-specific Baton says native occupied use is paused and Claude is not a
fallback, while the generic Authority Allocation section still describes
Claude Code as the preferred DeepSeek transport. The specific live Baton
controls, but a machine-readable allocation should not make the orchestrator
resolve contradictory prose.

## Ranked options

1. **Recommended: fold prospective evidence validation and transaction-fact
   derivation into the existing tick.** Validate every prospective plan,
   closeout and acceptance timestamp before publication, return the complete
   error set, and make attempts, leases, generations and rollbacks generated
   outputs. In the latest sample this removes three rollbacks and three rerun
   sequences with zero new operator fields, gates or documents.
2. **Later: typed semantic closeout builder and command registry.** This could
   make 11 of the latest 12 lapses, and as many as 30 of the 31 sampled lapses,
   impossible or unnecessary. It should follow a matched measurement of option
   1 so it does not become a new bureaucracy layer.
3. **Reject: relax the checks.** That hides mistakes by weakening safety.
4. **Reject: leave the interface unchanged.** The measured closeout cost is
   now too high relative to accepted development yield.
