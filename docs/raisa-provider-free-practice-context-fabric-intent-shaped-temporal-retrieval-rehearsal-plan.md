# Provider-free Practice Context Fabric intent-shaped temporal retrieval rehearsal plan

Date: 2026-08-06

Status: frozen bounded implementation plan

Parent result:

## Objective

Prove that one typed user-intent candidate can be converted into the smallest
authorised, expiring and immutable Context Fabric packet assembled from the
already accepted Current operational weave, Bureau Memory Bank and patient-free
historical weave. The candidate may describe a need; backend policy alone binds
identity, practice, session, purpose, Bureau, time, fields and disclosure limits.

The exact result label is
`raisa_provider_free_practice_context_fabric_intent_shaped_temporal_retrieval_rehearsal_pass`.

This is the first deterministic rehearsal of how independently governed Bureaus
may interweave through the Fabric. `RECEPTION ONE(TM)` and the candidate
`Clinician One` remain branded workspace/projection families, never authority
domains. Every component is admitted by atomic Bureau capability and purpose.

## Inputs

Only repository-authored synthetic, patient-free objects are eligible:

1. one sealed `IntentRetrievalCandidate` using a closed intent code and bounded
   temporal/disclosure hints;
2. one backend-owned `IntentRetrievalAuthorityBinding` with exact
   principal/practice/session generation, policy, Bureau, purpose, component,
   field, time, freshness, cardinality and byte ceilings;
3. the exact accepted authored-synthetic Current operational weave packet,
   treated as one four-source coherence component;
4. the exact accepted Bureau Memory packet and its proofread frame set; and
5. the exact accepted patient-free historical policy, snapshots, results and
   temporal state.

The candidate cannot supply or override identity, role, practice, location,
session, retention, provider, source truth, clinical authority or command
authority. It contains no patient identity, name, free text, SQL, vector query,
prompt or arbitrary source selector.

## Closed intent vocabulary

- `CURRENT_OPERATIONAL_STATUS`: current coherent operational component only;
- `RECENT_PRACTICE_WORK`: Bureau Memory component only;
- `HISTORICAL_OPERATIONAL_STATE`: one bitemporal historical selection only;
- `CURRENT_AND_PRIOR_OPERATIONAL_COMPARISON`: current plus historical; and
- `RECENT_OPERATIONAL_REFERENCE`: bounded opaque alternatives from already
  admitted recent-work context, never an asserted identity.

An explicit mapping normalises the accepted lowercase Memory vocabulary and
uppercase Current/Historical vocabulary. Implicit case folding, string guessing
and brand-derived Bureau selection are forbidden.

## Outputs

- one sealed `IntentRetrievalPlan` derived from the closed intent template and
  narrowed authority binding;
- one deterministic component-selection trace with admitted and omitted reasons;
- one immutable `IntentContextFrameSet` containing only admitted component
  frames and exact upstream digests/provenance;
- an ambiguity result of `NONE`, `ALTERNATIVES` or `NOT_AVAILABLE`;
- one same-packet proofreader trace that independently recomputes the plan,
  selection, minimisation, temporal validity and digests; and
- a closed JSON Schema, admitted example, deterministic acceptance evidence and
  focused tests.

## Deterministic lifecycle

1. Verify every upstream seal and require its accepted proofreader decision.
2. Canonically map the closed candidate intent to exact required/optional
   components, purposes and shareability rules.
3. Intersect the template and candidate with the backend binding. Empty required
   intersections return uniform `NOT_AVAILABLE` without counts or partial data.
4. Treat the four-frame Current operational weave as one atomic coherence
   component; minimise its disclosed fields without weakening its source set.
5. Exclude private-session Current material from a cross-Bureau packet. Shared
   recent work requires bilateral typed Bureau scope and purpose.
6. Select historical material by both `valid_at` and `known_at`. A gap is an
   explicit coverage result, never evidence of absence.
7. If two or more equally admissible opaque recent-work matches remain, return
   canonical alternatives and a safe discriminator request; choose none.
8. Immediately before release, reject an expired/superseded upstream set,
   `REASSEMBLY_REQUIRED` temporal state, session-generation mismatch or stale
   result revision.
9. Proofread the exact candidate, binding, plan, upstream components, selection
   and output in one packet. Any mismatch blocks the whole release.

## Data, provider, cost and licence posture

- Data: newly authored synthetic opaque references, counts and operational codes
  only; no patient, clinical, product-derived or protected material.
- Provider and external retrieval: none.
- Cost: zero provider/cloud cost.
- Licence: no external corpus, content or licence surface.

## Allowed side effects

Repository writes are limited to this plan/design/threat delta, one pure
retrieval engine, a closed schema/example/evidence directory, one acceptance
generator, focused tests and later acceptance/continuity artifacts. The engine
has zero filesystem, network, database, subprocess, provider, product-runtime,
listener, API or command effects.

## Forbidden surfaces

No `app/**` or `docs/diary/**` change or import; no GraphQL extension, root,
resolver, route, mutation or subscription; no REST/OpenAPI command; no live
database, event feed, watcher, source reader, persistence or retention choice;
no model/provider call; no patient/product/protected data; no clinical,
prescribing, referral, billing or financial decision; no runtime, deployment,
production, release, Pages, protected evidence or protected-ref movement.
Preserve and exclude `docs/branding/` and unrelated untracked artifacts.

## Acceptance

1. All objects are closed and schema-valid; candidate authority injection fails.
2. Closed intent mapping is explicit, canonical and independent of brand names.
3. Current-only, Memory-only, Historical-only and Current-plus-Historical intents
   release exactly the required granted components and no others.
4. The Current component retains all four coherent source frames while fields,
   items, time, count and bytes only narrow.
5. Cross-Bureau private-session material is blocked; shared recent-work requires
   bilateral scope and provenance.
6. Two equally admissible opaque references produce deterministic
   `ALTERNATIVES`, never arbitrary identity resolution.
7. Missing required coverage, expired inputs, stale session/generation,
   superseded frames and temporal invalidation return `NOT_AVAILABLE` or block
   release without partial disclosure.
8. `valid_at`/`known_at` reproduces known-then versus corrected-later historical
   state; explicit gaps remain gaps.
9. Every released frame retains exact upstream digest, source revision, binding,
   policy, purpose, expiry and read-only/no-command authority.
10. Same-packet proofreading blocks over-disclosure, provenance tamper, resealed
    candidate/binding mismatch and stale-state substitution.
11. API Spine regressions prove no new API or command surface; static/runtime
    counters prove zero provider, network, database, subprocess, filesystem-write,
    product-runtime, listener, command, deployment and protected actions.

## Recovery and stop

Any schema, deterministic, temporal, source-binding, privacy, security or
regression failure blocks evidence regeneration and independent review.
Mechanical repairs remain inside the exact tranche file set. A material semantic
conflict returns to Sol's recovery lease. No partial or incompletely proofread
packet is released.

## Claim boundary and next dependency

Passing proves only an unmounted, pure authored-synthetic intent-to-context
retrieval contract. It does not prove natural-language intent classification,
provider-model behaviour, product or patient privacy, live retrieval, database
watching, production retention, runtime performance, cross-Bureau clinical
handoff or command safety.

After acceptance, a separately bounded descendant may rehearse the same closed
contract through an occupied model envelope. Real product reads, patient data,
clinical evidence and Bureau commands each require their own later authority.
