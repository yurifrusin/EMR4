# Threat-model delta — Raisa Word Online authenticated companion verification

Date: 2026-07-31

## Added surface

The exact public Sydney development host now permits the two capabilities
needed by the already accepted provider-free companion:

- `smoke`; and
- `reception_one_companion_demo`.

This applies only when the dynamically served hosting policy matches the
current HTTPS `run.app` origin, classifies the data as authored-synthetic and
sets backend, provider, credential, microphone, command, document-write and
production authority to false.

## Threats and controls

| Threat | Control |
|---|---|
| An arbitrary remote host activates local harness features | The hosted predicate requires the exact origin-bound public policy and a `run.app` HTTPS hostname. |
| A query parameter activates broader development capabilities | The hosted allowlist contains exactly two capability names; product-context, Bernie review, confirmation-adapter and slot-preview flags remain rejected. |
| Hosted smoke mode reaches an EMR backend or provider | The static host exposes no API route, the CSP keeps `connect-src` closed, and browser resource timing is checked for API, credential and provider endpoints. |
| Appointment detail escapes into Word | The Diary proofreader returns the existing exact generic summary manifest; Word independently revalidates it and renders copy from codes. |
| A Word document or account identifier enters evidence | Evidence records only host class and boolean outcomes; no account, tenant, document URL, document identifier or filename is retained. |
| The add-in gains document-write authority | The manifest remains `ReadDocument`; the taskpane performs no Word document-body read or write in this companion path. |
| Failure is mistaken for success | The first hosted attempt released no summary. Only the post-repair exact generic summary is accepted. |

## Residual limits

The result is a development-host, authored-synthetic proof. It does not
establish EMR4 authentication, clinician authorization, organisational
deployment, real-data safety, backend authorization, provider safety,
production fitness or release readiness.
