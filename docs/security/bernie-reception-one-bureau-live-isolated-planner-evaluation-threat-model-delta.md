# Threat-model delta: Bureau live isolated-planner evaluation

The new trust crossing is one visible development-only `isolated_vertex`
selection traversing the real local browser, authenticated proposal route,
trusted context desk, credential-free work cell, one-use broker, exact Sydney
Vertex endpoint, deterministic proofreader and proposal renderer.

Controls:

- authored-synthetic practice and development gates remain exact and default
  off;
- visible selector submits only the closed planner enum;
- absolute occupied provider-call ceiling is one, with no correction call;
- backend alone owns database reads, raw identifiers, freshness and adapters;
- cell receives opaque typed context only, with no credential, database or
  product network access;
- broker alone uses existing keyless impersonated ADC;
- exact provider/model/project/service-account/region/hostname binding;
- no API key, static key, global endpoint, provider/region fallback,
  deterministic fallback, tools, grounding, retrieval or cache creation;
- deterministic proofreader is the sole release gate;
- browser receives only admitted typed fields and bounded non-secret
  provenance;
- no confirmation or mutation affordance is added;
- database hashes and counts are compared before and after;
- every opened ledger is consumed; and
- exact process, port, directory, token, container, image, network and database
  residue is independently checked.

Fail closed on unknown or hidden planner selection, non-synthetic scope,
credential or identifier leakage, stale context, authority/preflight revision
drift, provider binding mismatch, a second call attempt, proofreader
non-admission, unverified browser output, fallback, database change or cleanup
residue.

Residual risk is limited to one authored-synthetic development request. The
result cannot prove general model reliability, real-data safety, production
fitness or Australian physical or sovereign processing.
