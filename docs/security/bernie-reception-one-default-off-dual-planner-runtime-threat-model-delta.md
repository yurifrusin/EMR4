# Threat-model delta: default-off dual-planner product-context runtime

The new trust crossing is an explicit `isolated_vertex` selection on the
existing authenticated development proposal route. The selected planner may
consume the trusted backend's minimal frame but gains no product or command
authority.

Controls:

- route default off, isolated planner separately default off;
- development environment, authored-synthetic class and exact practice
  allowlist all required;
- closed planner enum; no caller-supplied provider, model, project, identity,
  hostname, region or credential field;
- trusted backend owns database reads, raw identifiers, availability and
  proposal adapters;
- request-scoped opaque handles only in the cell;
- credential-free, non-root, read-only, bounded, network-isolated cell;
- purpose-built one-use broker with exact Bernie keyless-ADC Sydney allowlist;
- no provider fallback and no deterministic fallback after selecting Vertex;
- request wall clock hash-bound through frame, desk context and proofreader;
- proofreader-admitted release only; correction limited to one;
- common proposal-only response with confirmation and writes false;
- durable sanitized audit, consumed ledgers and post-run residue verification.

Fail closed on disabled gate, non-dev environment, practice or data mismatch,
freshness mismatch, frame or source-label drift, unexpected model-visible
field, identifier or credential leakage, provider binding mismatch, broker or
cell error, proofreader rejection, open ledger, database mutation or cleanup
residue.

Residual risk is limited to this disposable authored-synthetic development
surface. No claim is made for production fitness, real-data safety, exhaustive
language behavior or Australian physical or sovereign processing.
