# Threat-model delta: post-sentinel pre-stock-readiness exit-coordinate diagnosis

Date: 2026-08-21

## New evidence surface

The tranche reads one sanitized failed terminal, its immutable consumed ledger
and contract, repository controller/profile source, and exact pinned rc.7 source.
It writes deterministic source-coordinate evidence only.

## Threats and controls

- **Raw-stream reconstruction:** the retained stderr digest could be treated as
  an oracle. The implementation neither reads that digest nor retains or guesses
  stderr text, a stack, a raw path, environment data or session material.
- **Execution disguised as diagnosis:** importing a controller or checking the
  JavaScript through Node would reopen the consumed attempt. All sources are read
  as inert bytes; executable Harness activity counters remain zero.
- **Post-hoc causal overreach:** an empty task may be convenient but not actually
  connected to exit. Acceptance requires every exact source link from the empty
  argument snapshot through startup rejection, Commander, `ctx.appExit` and
  profile shutdown.
- **Negative-patch ambiguity:** absence of a disabling row could be mistaken for
  proof of activation. The exact bundle insertion and exact user override are
  both bound; the terminal's sentinel event fixes the observed ordering boundary.
- **Observed-code coincidence:** terminal exit `1` alone is not causal proof.
  Hostile mutations independently remove or alter each source link and must force
  `insufficient_static_evidence`.
- **Repair smuggling:** diagnosis does not supply a task, mutate the profile or
  authorise a fresh process. Any later repair/proof requires a new contract and
  attempt identity.
- **Workflow drift:** canonical continuity surfaces are changed only by the
  governance clockwork, never by direct latch edits.

## Unchanged boundaries

No product or clinical surface is opened. No provider request, live data,
deployment, release, Pages action, protected-ref change or ordinary-practice
enablement is authorised.
