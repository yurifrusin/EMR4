# Threat-model delta — provider-free repaired-sentinel native boot proof

Date: 2026-08-21
Status: frozen

## New executable surface

One disposable local rc.7 Node/Harness process loads the repaired initial
headless profile. It is a pre-provider HMR-readiness probe only.

## Threats and controls

| Threat | Fail-closed control |
|---|---|
| A profile-relative module escapes to an unintended file | The exact relative row is generated by the accepted controller, the expected resolved file is written in the disposable installation proof directory, and no other proof module is present. |
| The changed runner or a worker is activated | Only `changed=False` is generated; runner rows and `runner.mjs` are rejected; no task argument, broker or worker session exists. |
| A configured plugin attempts provider/network access | Credential and proxy names are scrubbed; the accepted Node network guard denies and records network primitives; any record fails the attempt. |
| A retry hides a first failure | The attempt is exclusively consumed at the sole `Popen`; canonical outputs reject reuse; source inspection requires exactly one `Popen` and no retry loop. |
| Raw runtime output leaks data or credentials | The launch has no product data or prompt; streams remain in the disposable root; only counts/digests survive; raw bytes, environment, paths, messages and stacks are deleted. |
| A malformed event is mistaken for readiness | Exact schema, sequence, closed vocabulary and exact two-event terminal sequence are required. |
| Cleanup targets the wrong path | The root must be a direct nonsymlink child of the accepted disposable parent; the exact child is removed only after process termination. |
| A passing boot is overclaimed as worker reliability | The contract and result explicitly limit the claim to sentinel loading and stock-headless HMR readiness. |

## Residual risk

The proof exercises one local Windows process and one pinned prerelease Harness
build. A pass does not establish model/provider reachability, runner mounting,
worker correctness, multi-turn reliability, product safety or production
suitability. Those require separately frozen later tranches.
