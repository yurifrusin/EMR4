## New evidence surface

The tranche modifies one literal-prefix byte in the sentinel author and statically proves the generated JavaScript bytes. It reads accepted diagnosis and consumed-attempt evidence only to bind immutability.

## Threats and controls

- **Repair broadening:** a convenient rewrite could alter request, profile, tool or lifecycle behavior. The candidate must equal the planning-source Git preimage plus exactly one inserted `r` at the frozen literal prefix.
- **False JavaScript validity:** checking only source spelling could miss Python translation. The validator statically evaluates the AST literal and scans the actual generated bytes for raw CR/LF within regex and quoted-literal states.
- **Executable validation:** invoking Node or the Harness would exceed this tranche. The proof uses Git, Python AST and a bounded lexical scanner only, with all process/request counters fixed at zero.
- **Consumed-evidence mutation:** a repair could overwrite or reinterpret earlier failures. Every tracked file under the frozen consumed-evidence roots must equal its planning-source Git object.
- **Digest substitution:** abbreviated or guessed object IDs could bind the wrong source. Git sources are full 40-character IDs and the preflight machine snapshot owns current-ref evidence.
- **Premature success claim:** lexical validity does not prove that a later Harness boot will succeed. Acceptance proves only the source transformation and generated-byte property; any boot remains separately gated.
- **Workflow drift:** canonical baton, latch, Continuity, Compass and register surfaces remain clockwork-owned and may not be edited manually.

## Unchanged boundaries

No provider/model request, Node/Harness process, product or clinical surface, runtime, deployment, release, Pages action, protected evidence or protected-ref movement is authorised.
