# Ariadne risk-weighted workflow reform threat-model delta

Date: 2026-08-16

Timestamp: 2026-08-16T08:51:07+10:00 (Australia/Brisbane)

Status: `frozen`

Reasoning level: material workflow admission and authority policy / Extra High

## Boundary

This delta covers only the provider-free repository harness that classifies a
development tranche, selects proportionate deterministic/review evidence,
validates exact verifier paths and renders a non-executing closeout packet. It
has no Raisa product, runtime, database, provider or protected-ref authority.

## Assets retained

- five-source authority and the active-operation latch;
- protected evidence, patient/clinical data and provider boundaries;
- immutable rejected evidence and exact cleanup;
- exact candidate, worktree, command manifest and Git identities;
- semantic authority, atomicity, replay, privacy and irreversible-effect gates;
- independent veto when the deterministic risk classifier requires it; and
- explicit Sol acceptance and integration authority.

## Named threats and required controls

| ID | Threat | Required fail-closed control |
|---|---|---|
| `RWW-001` | Caller selects a lower ceremony tier | Tier is derived from closed change/risk signals; declared tier is rejected or compared only for equality. |
| `RWW-002` | `docs_only` or `unmounted` label hides executable, database, authority or provider scope | Contradictory combinations fail before a gate decision. |
| `RWW-003` | Baseline failures are rediscovered and misattributed to the candidate | Tier 1-3 require a pre-edit canonical fingerprint and named known-failure set. |
| `RWW-004` | A semantic edit is labelled metadata to suppress canonical rerun | Closed change families and semantic-binding comparison take the highest rerun union; unknown paths fail closed. |
| `RWW-005` | Closeout prose or receipt timestamps force product semantic hash cascades | Volatile evidence cannot enter semantic bindings and receives only targeted validation. |
| `RWW-006` | A stale exact pass is reused after source, evidence, input or toolchain drift | Reuse requires the full accepted gate fingerprint; otherwise run or resolve uncertainty. |
| `RWW-007` | Review stacking adds latency or conflicting quasi-authority | Exact tier/risk policy admits zero or one final veto; recovery creates a new final veto rather than concurrent reviewers. |
| `RWW-008` | Reduced review removes an authority/privacy/atomicity gate | Hard controls are invariant and Tier 2-3 veto requirements cannot be overridden by profile data. |
| `RWW-009` | Mutation volume substitutes for missing threat coverage | Every named threat maps to at least one passing gate; count is advisory only. |
| `RWW-010` | Incident batching erases a failed attempt or allows retry first | Minimal typed incident evidence precedes corrected admission; only narrative aggregation is deferred. |
| `RWW-011` | Several distinct failures are collapsed into one causal incident | Grouping requires exact origin/category/role/resource/signature equality. |
| `RWW-012` | Timeboxing defers a safety, authority, privacy or integrity defect | Deferral requires explicit false safety/authority flags plus owner and next review boundary. |
| `RWW-013` | External verifier runs candidate-relative tests from the primary checkout | Serial runner binds an exact candidate repo root and preflight validates manifest path/root relationships without execution. |
| `RWW-014` | Shared interpreter/tool paths are mistaken for candidate source or broadened silently | External paths require exact typed allowlisting; candidate paths remain inside the review worktree. |
| `RWW-015` | Generated closeout text silently changes authority, acceptance or programme state | Renderer emits documents/payloads only to explicit paths; it never applies AGENTS, Continuity, Compass, Git or latch changes. |
| `RWW-016` | A generated result claims pass without tier-required evidence | Result admission derives required evidence from the bound profile digest and rejects omission, contradiction or excess reviewer claims. |
| `RWW-017` | Receipt reduction skips a configured high-authority transition | Only microstep duplication is suppressed; every configured continuation event actually crossed still requires a fresh five-source receipt. |
| `RWW-018` | Parallelism is silently ignored in the name of efficiency | Profile and result preserve explicit DeepSeek, Gemini and native-lane dispositions plus planned-versus-actual comparison. |

## Misuse cases

- A Tier 2 migration profile sets `docs_only=true`.
- A post-freeze policy edit is declared `closeout_prose`.
- A product contract hashes its current latch or reviewer receipt.
- A Tier 3 result supplies no independent review or supplies two concurrent
  reviewers.
- A failed canonical gate is rerun unchanged rather than diagnosed.
- A manifest invokes the primary checkout's serial runner with relative tests
  that exist only in the review checkout.
- A renderer is asked to overwrite AGENTS or the live latch.

Each must return `revision_required` or raise deterministic validation error
before execution, external review or acceptance.

## Residual risks and claim limit

The classifier depends on truthful complete profile inputs, so exact owned-path
and Git-diff inspection remains a Sol responsibility. The renderer reduces
manual duplication but cannot determine whether an architectural claim is
true. Runtime speed improvement remains unproved until later tranche metrics
compare planned with actual gates and elapsed stages.

No hard authority, privacy, evidence, cleanup, product/runtime or protected-ref
boundary is weakened by this delta.
