## Scope

This delta covers one live provider-free semantic governance tick through the
accepted bound driver. No product or protected integration is in scope.

## Threats and controls

| Threat | Control |
|---|---|
| Conditional closeout prose is mistaken for evidence before the driver finishes | Every conclusion is explicitly conditional on one zero-exit fixed driver result; failure triggers rejection and, if committed, byte-exact rollback. |
| The driver publishes but skips or weakens postpublication verification | The five-file selection is a closed constant; the driver returns success only after it passes with unchanged tracked status. |
| A second manual live reading recreates the redundant operator step | Accept the publisher's inline validated state and record manual readback count zero. |
| Caller Python or a short Git abbreviation leaks into the tick | Select and attest the repository interpreter; machine-resolve HEAD and accept no caller-authored object ID. |
| Postpublication failure leaves misleading canonical state | Preserve the failure and invoke the established byte-exact rollback once; do not retry or switch writers. |
| The stage manifest omits a changed canonical file or admits unrelated material | Recompute Git's NUL-delimited tracked/untracked inventories independently and require exact set equality at the driver completion boundary. |
| `docs/branding/` or historical untracked files are swept into closeout | Branding is forbidden, unrelated untracked files are excluded and the index must remain empty. |
| Successful governance use is overgeneralised | Adoption is limited to the exact provider-free semantic governance profile; product, worker, provider, data, production and protected surfaces need separate authority. |

## Claim boundary

This review can adopt one deterministic governance entrypoint. It cannot
qualify another harness, remove tests, stage files, or change product,
production, deployment, release, Pages or protected integration authority.
