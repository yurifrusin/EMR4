## Threats and controls

| Threat | Required control |
|---|---|
| Presentation similarity is mistaken for truth parity | Compare only the frozen kernel-owned coordinate, proposal, confirmation, result, current-truth, terminal-display and route-count fields; keep layout, wording, focus and history in a separate renderer-local object. |
| A real renderer mismatch is hidden by normalization | Exact enums and pairwise equality are fail-closed; unknown or missing fields, duplicates and mismatches fail. Product repairs are outside this tranche. |
| The trace becomes a runtime or audit contract | Keep it under orchestration continuity evidence, forbid imports from product source, and state that it is not API, database, analytics, transcript, event or audit evidence. |
| A second command path is accidentally exercised | Permit only the existing status proposal and status-confirm endpoints; count and reject raw compatibility or unexpected mutation requests. |
| Intercepted evidence is described as live | Label every browser trace `route_intercepted_browser`; claim no backend, database, provider, deployed or production operation. |
| Fixture content resembles real patient data | Use newly authored synthetic identity only in ephemeral browser memory; omit names and demographics from the committed trace. |
| Local renderer differences are forced into a grid-shaped UX | Explicitly permit distinct layout, wording, focus target and local history while requiring identical kernel meaning. |
| Stale, blocked, cancelled or failed UI is mistaken for current truth | Require unchanged fixture truth and unchanged displayed terminal status, one normalized no-commit result and zero raw fallback. |
| A committed display is optimistic | Require the intercepted source fixture to contain the committed status and require the renderer to display that same terminal status after its existing reconciliation path. |
