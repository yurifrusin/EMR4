## Frozen implementation shape

### Gear 1 — prospective success projection

The base harness owns a pure `_prospective_success_evidence_projection`
function. It returns a complete, schema-valid, sanitised structural
representation of the possible final success evidence using only local
contract values, full Git objects and bounded placeholders.

The static admission path must, in this order:

1. validate the canonical contract and existing hostile mutations;
2. construct the prospective projection;
3. derive the exact runtime result key-path surface from the current source AST,
   including finalized cleanup, scenario item and contract-derived closed-
   boundary paths;
4. require exact equality with the prospective projection's normalized key-
   path surface;
5. run the complete projection through the unchanged `_assert_redacted` with
   an empty forbidden-value tuple; and
6. require zero evidence-schema errors.

Any mismatch or collision fails static admission before `_docker_executable`,
image inspection, secret generation or any lifecycle work. The static result
records bounded projection path count, redaction status, schema status and
hostile rejection counts, but no raw source or values.

Hostile projection tests inject exact-token, prefix and suffix forbidden keys
at top-level and nested coordinates; all must fail as
`redaction/forbidden_field`. Safe near-misses must remain admitted. A deleted,
extra or renamed runtime/prospective path must fail parity.

### Gear 2 — typed post-finalization terminal bridge

The base harness owns one frozen dataclass:
`PostFinalizationTerminal`, containing exactly `evidence` and optional
`attestation`. A pure `_finalize_post_cleanup_terminal` helper accepts the
candidate result, attestation, any earlier typed `RehearsalFailure`, lifecycle,
the already-finalized cleanup dictionary, elapsed time and bounded forbidden
values.

The helper alone owns all post-`finally` decisions:

- an earlier error or missing candidate becomes sanitised failure evidence;
- finalized cleanup and elapsed time are attached to a candidate success;
- final redaction failure becomes sanitised failure evidence with the exact
  finalized cleanup projection;
- evidence-schema failure becomes sanitised failure evidence with that same
  cleanup projection;
- failure evidence is itself redacted before its exclusive terminal write;
- only a fully redacted, schema-valid success writes attestation and success
  evidence; and
- every branch returns `PostFinalizationTerminal` rather than allowing an
  intended late `RehearsalFailure` to escape.

`run_rehearsal` retains its public tuple return for compatibility by unpacking
the typed terminal. Attempt 007's historical wrapper is not modified and its

must prove that a base-owned late failure now arrives as failure evidence whose
