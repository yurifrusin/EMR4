# Bernie/Davida parallel seam plan

Date: 2026-08-03

Status: authorised and frozen

Reasoning level: GPT Sol Extra High for the material architecture, authority
and security boundary; High for bounded artifacts, tests and task-branch
mechanics.

## Objective

Freeze the smallest shared architecture that lets two bounded product lanes
progress concurrently without giving either probabilistic agent database or
command authority:

1. continue the already selected default-off application-session native Diary
   composition review for the existing active-practitioner read, while leaving
   the current bearer-authenticated GraphQL/REST-fallback path unchanged when
   the feature is off; and
2. define Davida as the practice-operations custodian over authoritative
   slowly-changing practice state, provenance-bearing advisory knowledge and
   bounded session state.

This tranche changes no product runtime. It creates no model, provider,
container, route, database migration, product read, command, deployment or
protected-ref movement.

## Standing authority

Yuri authorised the root Sol/Ariadne conductor to move from tranche to tranche
in both lanes without repeated permission when the next step is a bounded,
logical descendant of this frozen direction. That standing authority includes
architecture, implementation, deterministic tests, evidence, isolated worker
dispatch, contained repair, non-protected task-branch commits and non-protected
pushes.

The root conductor must stop for a material architecture or product-behaviour
fork; real patient, clinical, identity or production data; new provider/model,
material cost or licence authority; autonomous or model-to-database authority;
cloud/IAM, deployment, production, release or protected-ref movement; protected
evidence/holdout expansion; irreversible external action; a direction-changing
security finding; or a simple manual Office/browser/computer action that Yuri
can perform materially more economically than token-heavy computer control.

## Frozen architecture decisions

- Bernie and Davida are separate bounded probabilistic work cells and future
  deployment identities. They may share a hardened base image and code, but
  not an ambient capability union, database identity or runtime policy.
- The deterministic agent kernel is shared as code and contract. Each agent
  receives a separately pinned proofreader policy and capability manifest.
- The proofreader is outside the probabilistic work cell and is its only egress
  path. Proofreading releases evidence-bounded drafts, never commands or facts.
- The deterministic native Diary consumer is not an agent and does not pass
  through Bernie, Davida or either agent proofreader. It may reuse the lower
  authenticated application-session/product-read bridge only.
- The Office one-use terminal reload/logout lifecycle is surface-specific and
  must not be reused for the long-lived native Diary composition.
- EMR4's typed backend remains the sole database and command authority.
- GraphQL supplies named, scoped read/context frames only. Auditable or
  state-changing work uses explicit REST/OpenAPI proposal and confirmation
  commands. Committed events trigger fresh reads and never grant action.
- Authoritative structured practice state, advisory institutional knowledge and
  conversational/session state remain three distinct stores and authority
  classes.
- Practitioner lifecycle truth belongs to the backend practice domain. The
  existing active-practitioner projection is a shared read model consumed by
  Diary, Bernie and future Davida surfaces; no agent owns or caches competing
  truth.
- Initial setup compiles to the same typed practice-administration command
  vocabulary as ongoing management. YAML remains declared input, not an
  executable or shadow policy engine.
- Davida emits intent, clarification, explanation and proposal drafts only. A
  Davida/model output must never instantiate a confirmation or
  `writes_authorized=true` envelope; trusted backend code constructs command
  authority only from an authenticated human action.

## Parallel execution contract

The two lanes may draft and implement independently only after this seam
contract passes deterministic acceptance. Each lane has its own non-protected
worktree, branch, source-head binding, scope packet, owned paths and forbidden
paths. Workers never edit `AGENTS.md`, Continuity/Compass, integration logs,
shared harness settings or `docs/branding/`; the root Sol conductor owns shared
reconciliation and acceptance artifacts.

Repository pytest processes that load `tests/conftest.py`, all shared
PostgreSQL use, the one Antigravity Gemini verifier and integration remain
serial. Independent static/filesystem checks and isolated browser checks with
no shared mutable runtime may run concurrently.

No Ariadne Python change is required before dispatch. The current verifier and
sprint-worker policies plus exact lane packets are sufficient. Dispatch must
not use the `agent_worktrees.py` commit-message path because it stages with
`git add -A`, which is incompatible with the protected user-owned branding
directory. It must not use the legacy advisory allocator for reviewer choice;
the authoritative verifier policy selects Gemini 3.6 Flash/high.

Lane reviewers return exactly one `pass` or `revision_required` decision from a
fresh read-only candidate binding after deterministic gates pass. The root Sol
conductor alone accepts, reconciles and integrates task candidates.

## Acceptance

- The machine-readable contract validates against its schema.
- Tests prove separate agent runtimes and identities, shared-code/separate-policy
  proofreading, no probabilistic database access and no model-to-database path.
- Tests prove the three memory/state authority classes remain distinct.
- Tests prove the active-practitioner projection has one backend owner and only
  read consumers.
- Tests prove GraphQL reads, REST/OpenAPI commands and committed-event semantics
  remain distinct.
- Tests prove shared paths, PostgreSQL, Gemini review and integration are
  serialized or root-owned while independent work can parallelize.
- Existing API Spine artifact tests and verifier-policy tests pass unchanged.
- `git diff --check` passes and `docs/branding/` remains absent from the index,
  test scope and intentional patch.

## Lane sequence after acceptance

### Diary lane

1. Architecture/composition review of a default-off application-session native
   Diary consumer of the existing active-practitioner read.
2. Provider-free unmounted composition contract plus direct HTTP/PostgreSQL
   evidence, with no native Diary asset edit.
3. Default-off native Diary UI wiring while the existing bearer path remains
   unchanged when the feature is off.
4. Non-intercepted live-local browser/backend/PostgreSQL acceptance only when
   the exact path is actually exercised and correctly labelled.

Every write, provider, real identity, deployment and default-on switch remains
closed.

### Davida lane

1. Architecture-only Practice Administration bounded-context and capability
   taxonomy.
2. Provider-free typed read-frame and dry-run proposal contracts over authored
   synthetic locations and practitioners.
3. One reversible administrative proposal vertical with no apply command.
4. A later human-confirmed command candidate only after the preceding contract
   and risk tier are accepted without a material fork.

The current memory/RAG/GraphRAG, live provider, external identity write and
model-to-database gates remain closed.

Before an actual apply command, Practice Administration must add a closed
operation enum, uniform optimistic-concurrency revision or ETag, idempotency,
append-only audit/outbox semantics and human confirmation. Existing direct
room/waiting-area CRUD is not that command plane, and current GET paths that
normalize and commit cannot be reused as pure Davida read projections.
