# Raisa provider-free OIDC admission-grant redemption bridge plan

Date: 2026-08-02

Status: authorised implementation tranche

Parent: `raisa-provider-free-oidc-binding-admission-grant-boundary`

## Outcome sought

Redeem one exact active 60-second authored-synthetic admission grant in its
original cookie partition, recheck the current binding and fresh internal
security-principal truth, and atomically create one accepted application parent
and surface session. Set the frozen surface and CSRF cookies only after the
database transaction commits.

It may not call Microsoft or another provider, use a real tenant or identity,

## Frozen contract

1. The new route is present but default-off. It opens only when a task-scoped
   redemption transport and the accepted operational guard are explicitly
   injected; no environment switch or composition root enables it.
2. The original surface submits the raw grant in a bounded JSON body with the
   frozen surface enum and the existing pre-authentication CSRF cookie/header.
   Exact origin comes only from the reviewed request boundary.
3. The service validates and HMACs the raw 256-bit grant before SQL. Raw grant,
   session, parent and CSRF values never enter a URL, database, log, audit or
   evidence artifact.
4. One finite `NOINHERIT` login has membership in one no-login redemption-call
   capability. The call capability can execute only the exact redemption
   function and perform the already accepted application-auth state/audit DML;
   it has no direct federation binding, grant, federation-audit or principal-
   truth privilege.
5. A separate ungranted `NOLOGIN` owner owns one empty-search-path
   `SECURITY DEFINER` function. Under exact forced-RLS context it locks the
   grant, verifies active/version-one/unexpired state and exact surface,
   origin, audience-HMAC and policy, and distinguishes only a committed replay
   from a generic rejection.
6. The function re-resolves the exact active binding by the grant's immutable
   binding reference, version, user and practice. It then locks one repository-
   local authored-synthetic security-principal truth row and requires current
   user, practice and membership state, a bounded backend role, and a current
   practitioner link when one exists. This table has no product foreign key or
   product-data import.
7. Known expired, context-mismatched, binding-changed or inactive-principal
   failures append a bounded federation rejection audit and release no
   authority. Unknown grants are covered by the accepted retained transport-
   denial audit without creating an identity oracle.
8. On success the function atomically changes only `active` version one to
   `consumed` version two, records `consumed_at`, and appends
   `federation.admission_grant_consumed`. Audit failure aborts the transition.
9. Before that transaction can commit, the accepted
   `ApplicationAuthRuntime` policy engine and PostgreSQL coordinator create one
   parent and exact surface binding for the freshly loaded principal, storing
   only SHA-256 references and appending the existing required session-created
   and surface-bound audit events. No duplicate session policy engine is added.
10. Grant consumption, federation audit, principal-generation lock, parent and
    surface inserts, and application-auth audit commit once. Any runtime,
    database, audit or commit failure rolls back every effect and releases no
    cookie. Concurrent redemption admits at most one session.
11. Only after known commit does the route set the accepted
    `__Host-emr4-application-session` and `__Host-emr4-application-csrf`
    cookies and return the CSRF value once under no-store headers. Callback
    continues to set no cookie.
12. The resulting session remains authored-synthetic and authorizes no product
    read. Every later request still requires the accepted backend validation
    and an endpoint-owned authorization decision.

## Acceptance

- A disposable PostgreSQL database migrates to the single new head and
  provisions uniquely named finite login, redemption-call and ungranted owner
  roles with no superuser/create/inherit/replication/bypass-RLS attributes.
- Direct login/call access to federation bindings, grants, federation audit and
  principal truth is denied; owner access to application-session tables is
  denied; the call capability retains only the accepted auth-session DML.
- One real loopback HTTP redemption consumes one issued grant, proves the exact
  current binding/version and fresh synthetic principal truth, commits one
  parent/surface session plus required audit, and sets exact cookies afterward.
- Replay and two-session concurrency admit exactly one consumer; expired,
  wrong-origin/surface/audience/policy, revoked binding, changed binding version,
  inactive user/practice/membership and stale practitioner link fail closed
  without a session or cookie.
- Forced federation-audit, application-audit, session-write and commit failure
  roll back grant consumption and all session state.
- Database/evidence residue contains no raw grant, parent, surface, CSRF,
  external identifier, provider token or key; no provider or product read
  occurs; server, database and every task role are removed.
- Focused and inherited API/auth/security/continuity checks pass, with any
  unchanged repository-wide collection barrier reported exactly.
