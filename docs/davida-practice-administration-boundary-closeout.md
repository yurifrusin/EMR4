## Accepted result

The first Davida descendant of `bernie_davida_parallel_seam_pass` is accepted
as an architecture-only, provider-free and non-executing boundary. Davida is a
separate practice-administration custodian identity over a shared
provider-neutral mechanical kernel, with separately pinned policy, scope,
memory and credentials. Database truth and command authority remain solely in
the typed backend.

Davida receives no database credential, ORM session, generic database client,
GraphQL mutation, REST command credential or event actuator. The read/context
desk admits only pure practice-scoped projections. The current room and
waiting-area GET paths are blocked because they normalize and commit during a
nominal read; the live appointment waiting-room path is blocked as patient-
linked data. The first operation vocabulary is exact and closed. Davida emits
only proofreader-admitted advisory drafts or non-mutating proposal candidates,
never confirmation, signed commands, `writes_authorized=true` or a mutating
release envelope.
