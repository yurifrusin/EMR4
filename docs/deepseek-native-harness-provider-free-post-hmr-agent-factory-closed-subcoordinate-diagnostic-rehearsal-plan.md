## Runner architecture

The HMR-loaded wrapper imports only Node built-ins statically. Package and guard
imports occur sequentially inside the guarded asynchronous transaction, so an
import/linking failure becomes a typed subcoordinate rather than preventing
`apply()` from installing its observer.

`apply()` first establishes its sidecar writer and `runner_apply_entered`
stage. The runner advances the stage variable only after each exact invariant.
Its one outer catch writes one exclusive typed failure sidecar and requests
clean exit. A success through the exact prepublication veto writes the separate
success coordinate. Sidecar preexistence, a second write, a resolved factory
handle, lifecycle publication, registry residue or any downstream request
rejects.

The controller independently joins the sidecar with readiness, HMR mutation,
process exit, broker zero, network zero, target absence, bundle immutability and
cleanup. If no sidecar exists, it may report only
`runner_link_or_apply_absence`; it must not project factory counts.
