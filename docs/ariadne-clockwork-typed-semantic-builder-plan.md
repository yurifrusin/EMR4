## Purpose

LLM form-filling exercise. The existing tick will accept one compact semantic
closeout intent, derive its fixed governance envelope and execute one closed
verification profile before publication.

This is the second measured ergonomic repair. It keeps the existing writer,
legacy intent support and rejection rules; it does not create a new workflow
system.

## Human-evidence header materialisation

Add one explicit semantic-intent-only CLI mode, `--prepare-evidence`. It will:

1. derive all prospective `plans`, `closeouts` and `acceptances` Markdown
   paths from the semantic profile;
2. derive one `Date:` and one Brisbane `Timestamp:` header from `recorded_at`;
3. leave an already exact header unchanged;
4. insert the exact pair after the first H1 when both are absent; and
5. reject the complete ordered conflict set before writing anything when a
   path is unsafe/missing, the first line is not an H1, or either header is
   present but not exactly derived.

The materialiser owns no canonical surface. It changes only the exact
uncommitted prospective Markdown files selected by the semantic intent, uses
atomic replacements with byte restoration on failure, and is idempotent.

Five documents therefore receive ten required Date/Timestamp scalar values
from one typed timestamp rather than ten independent free-form entries.

## Closed command registry and execution

The `governance_clockwork_core_v1` profile expands to exactly three serial,
shell-free commands:

1. parse the operation evidence JSON;
2. run Ruff over the three frozen implementation/test files; and
3. run the four whole-file governance suites through the provider-free pytest
   wrapper.

Semantic `--check` validates and expands the profile but does not execute it.
Semantic `--publish` executes the three commands exactly once before generation
preparation or any canonical write. It records command count, exit status and
output digests, rejects a failure or tracked-worktree drift as typed
`revision_required`, and reports zero publication and lease movement. No shell,
arbitrary executable, arbitrary test selector, environment mutation, provider,
database or network command is admitted.

Legacy intents retain their historical execution posture.
