## Closed containment wrapper

One closed `HostileContainmentAttempt` wraps an exact inherited C1 or C2
attempt and contains only:

- an outer scenario ID and one closed attack-family/carrier code;
- a short newly authored synthetic payload ID, UTF-8 byte count and SHA-256;
- the exact inherited base scenario ID and one statically coded mutation ID;
- generation, manifest, Bureau, work-cell and authority-binding identities;
- one authored-synthetic `ContextFrameSet` digest repeated as the candidate,
  proofreader and broker-observed context binding;
- an optional inert replay-artifact fixture whose kind is exactly `lease`,
  `alias` or `token`, with `synthetic_noncredential: true`; and
- exact expected status, reason, pure-call count and released-result count.

The scenario document is data, not an instruction language. Mutation IDs map
through one closed Python `if`/callable table written by the implementation;
the document cannot supply a path, attribute name, function, module, URL,
executable, expression or cleanup target. Extra or missing fields reject.

The wrapper status vocabulary is `contained`, `reject` and `stop`. Its reason
vocabulary is exactly:

- `exact_inert_control`;

## Two containment paths

### Opaque-value path

The harness may replace only the value of the already allowlisted C1
`typed-context` candidate field, synchronously in the C2 work-cell view and
broker admission copy. The value remains a bounded string. C1 admits the exact
unchanged operation identity; C2's broker-created invocation contains the
candidate digest and its two fixed authored-synthetic inputs, never the raw
hostile value. The pure adapter treats inputs as opaque and returns digests
only. A contained result must prove that the raw payload occurs nowhere in the
invocation, adapter result, returned C2 result, C3 evidence or exception
surface.

This path does not claim semantic detection. It proves that arbitrary content
inside the one allowed inert string has no interpreter, dereference, transport
or operation-selection path.

### Structural path

The harness may add one exact forbidden or undeclared field to a copied
work-cell candidate/view. Closed C1/C2 validation must reject it before the
pure adapter call. A structured attack is never repaired into an allowed
field, and its raw value is never copied into evidence.

## Output and egress containment

Five output attacks reuse only C2's exact
`adapter-result-contract-mismatch-stop` seam. The real pure function is called
once, then the authored-synthetic override is rejected by the exact C2 result
contract. No invalid result is released. Clear, encoded, compressed, chunked
and exception-labelled carriers receive no decoder or special channel.

Five separate budget attacks use exact 256-byte authored-synthetic values and
the same one fixed destination. Each starts with cumulative `total_bytes` at
12,033 against the inherited 12,288 ceiling and proposes 256 more bytes, so
12,289 stops before dispatch. Carrier labels do not change the charge. No
redirect or additional destination is permitted, and no payload is transformed
to discover a hypothetical decoded size.

## Cumulative stop sequences

1. `boundary-probe-denial-sequence-stop` runs two well-formed
   candidate-operation-identity denials. The broker-owned `denied_operations`
   and `boundary_probes` counts progress `0 -> 1 -> 2`; reaching the positive
   boundary-probe ceiling 2 latches `exhausted`. A third exact operation stops
   before dispatch with `budget_exhausted`.
2. `repeated-adapter-failure-sequence-stop` runs the exact malformed-result
   seam twice. Each pure call releases nothing and increments the broker-owned
   `repeated_failures` count. Reaching ceiling 2 latches `exhausted`; a third
   attempt makes no pure call. Counts and terminal state cannot be supplied by
   the work cell or transferred to another generation.

## Replay and identity checking

Every attempt compares current generation, manifest, Bureau, work cell,
authority and supply-chain identity before inherited admission and again before
the C2 pure call. Ending or restarting a generation invalidates the exact C1
lease and every inert alias/token fixture. Replay from another Bureau stops.
The wrapper never presents a lease, alias or token to the work-cell view.

The candidate, proofreader and broker must all carry the same admitted
authored-synthetic ContextFrameSet digest. A mismatch by either candidate or
proofreader stops before inherited simulation. Manifest, adapter-artifact,
runtime-image and model/provider-contract identities remain exact inherited
supply-chain checks; the catalogue challenges each required class represented
by the frozen scenarios.

## Generated hostile mutations

The acceptance harness independently mutates every required/closed wrapper
field, every enum, every expected count, every payload hash/byte count, every
context/replay identity and every inherited artifact digest. It also attempts
an unknown mutation ID, target path and carrier. Every mutation must reject or
stop with zero released result. It mutates each frozen nested C3 contract rule;
no changed but schema-shaped contract may validate.

## Static boundary

The C3 implementation must not import or call networking, HTTP/DNS, process,
environment, database, SQL, template, HDF5, pickle/serialization, archive,
compression, encoding/decoding, dynamic import or execution facilities. In
particular, `socket`, `requests`, `httpx`, `urllib`, `subprocess`, `os.environ`,
`pickle`, `marshal`, `shelve`, YAML object loaders, Jinja/template engines,
`h5py`, `base64`, `gzip`, `zlib`, `bz2`, `lzma`, `tarfile`, `zipfile`, `eval`,
`exec`, `compile`, `__import__`, reflection and plugin loading are forbidden.
All resource-like payloads remain literal strings. Exceptions fail the test
run; raw exception text is never normalized into evidence.

## API Spine classification

AES-C3 is an internal security rehearsal only. GraphQL remains read-only and
is not called. Events remain signals and are not consumed. Access AI remains a
future backend-brokered provider boundary and no provider/model runs. REST/
OpenAPI commands remain separate, current-authorized, human/policy-gated,
idempotent, audited and deterministically read back. Command-shaped candidates
are rejected and cannot invoke GraphQL, REST, SQL, a provider tool or a product
adapter.

The API Steward classification remains `internal_containment_evidence`; no API
schema, route, event family, context source, command or product behavior changes.

## Recovery, cleanup and claim boundary

A deterministic failure blocks external review. There is no runtime cleanup
because no process/service starts and all pure calls have no external state.
A need to inspect a referenced resource, decode content, use a real credential,
adapter, provider, source, network, tool or command is scope expansion and
stops C3.

Passing C3 will prove only the tested structural rejection, opaque digest-only
handling, result non-release, carrier-independent budget accounting,
cumulative terminal latching, stale-replay rejection and exact context/supply
binding for these authored-synthetic pure objects. It will not prove semantic
prompt-injection detection, process/container isolation, real credential or
adapter safety, provider behavior, concurrency, product-data safety, command
safety, deployment or production readiness.

AES-C4 is the next named programme descendant, but it is an occupied provider
proof and remains closed unless an exact current provider/data/cost envelope is
available under the controlling authority. C3 grants no provider call or C4
execution authority.
