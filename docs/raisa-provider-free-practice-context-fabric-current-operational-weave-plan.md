## Objective

Prove that the accepted Context Fabric can compose four already-authorised
operational read families into one typed, expiring and same-packet-proofread
bundle without creating a new product route, data source or authority path.

The exact result label is
`raisa_provider_free_practice_context_fabric_current_operational_weave_pass`.

## Inputs

Only repository-authored synthetic projections shaped from these existing read
families are eligible:

1. appointment-first Diary day read context from the API Spine;
2. Rayleen's freshness-bound waiting-room context frame;
3. the active-only application-session practitioner-directory read; and
4. bounded private application-session state containing visible Diary context,
   current focus and proposal-freshness metadata, never a transcript.

Every source arrives in a closed sealed envelope with an exact source-contract
id, practice and session binding, location scope, observation/expiry times,
source revision, evidence label and constant read-only/no-command/no-provider
ceilings. Source envelopes are supplied to a pure function; this tranche does
not call their product implementations.

## Outputs

- `OperationalContextNeedCandidate`, backend `OperationalAuthorityBinding`,
  `OperationalContextNeed` and narrowing `OperationalScopeGrant` objects.
- Four optional typed operational frames in a fixed canonical order.
- One `OperationalFrameSet`, exact source/weave trace and same-packet
  `OperationalProofreaderTrace`.
- Closed JSON Schema, one admitted example, deterministic tests and canonical-LF
  artifact evidence.

## Data, provider, cost and licence posture

- Data: newly authored synthetic identifiers and labels only; no patient,
  clinical, product-derived, historical-PHI or raw-audit material.
- Provider and external retrieval: none.
- Cost: zero provider/cloud cost.
- Licence: no external corpus, content or licence surface.

## Allowed side effects

Repository writes are limited to this plan/design/threat delta, one closed
schema/example/evidence directory, one pure engine, one acceptance generator,
focused tests and later acceptance/continuity artifacts. The engine itself has
zero filesystem, network, database, subprocess, provider, product-runtime or
command effects.

## Forbidden surfaces

No `app/**` or `docs/diary/**` change or import; no GraphQL root, resolver,
route, mutation or subscription; no REST/OpenAPI command; no real application
session, database or ordinary service; no persistence, temporal retention,
event stream, provider or external retrieval; no patient/product/protected
data; no deployment, production, release, Pages, protected evidence or
protected-ref movement. Preserve and exclude `docs/branding/` and unrelated
untracked receipt/state/evidence/cost-ledger files.

## Acceptance

1. Every object and nested payload is closed and schema-valid; authority fields
   are absent from the candidate.
2. Scope intersection can only preserve or narrow Bureau, purpose, frame,
   source, field, location, time, freshness, cardinality and byte limits.
3. Source contract, frame/source pairing, evidence/data labels and constant
   authority ceilings are allowlisted exactly.
4. Every admitted source matches the backend practice and session binding;
   locations are a subset of the grant; source time is current; required
   sources cannot be missing, duplicated, stale or superseded.
5. Cross-source coherence requires waiting-room appointment references to exist
   in the Diary frame, all practitioner references to resolve to active
   directory entries, and private session visible/focus references to match the
   same Diary/location.
6. Requested fields are intersected with backend field policy and projections
   expose only the resulting minimal field set.
7. Frames remain distinctly source-labelled and canonically ordered; no source
   is collapsed into another or treated as a command.
8. The same-packet proofreader recomputes exact need, grant, source, weave and
   frame-set digests and blocks expiry, tampering, authority mismatch or
   cross-source incoherence.
9. API Spine tests prove the existing GraphQL read graph is unchanged and no
   new GraphQL/REST product surface appears.
10. Static and runtime counters prove zero engine provider, network, database,
    subprocess, filesystem-write, product-runtime, command, deployment and
    protected operations.

## Recovery and stop

Any schema, deterministic, source-coherence, static or regression failure blocks
evidence regeneration and independent review. A mechanical repair remains
inside this exact file set. A material semantic conflict returns to Sol's
recovery lease. No failing, stale or partially admitted frame set is released.

## Claim boundary and next dependency

Passing proves only pure provider-free composition of authored-synthetic shapes
from four already-authorised read families. It does not prove a model-required
Bureau turn, product retrieval, real identity, database authorization,
persistence, retention, UI/runtime wiring, privacy adequacy or command safety.

The next dependency-satisfied descendant after acceptance is the separately
bounded patient-free temporal weave. This plan grants it no implementation
authority before the current tranche closes.
