# Reception One minimal read-only authored-synthetic Diary-context bridge

## Authority and predecessor

Yuri authorised this descendant only after the sealed v6.9 holdout passed. The
predecessor is
`reception-one-receptionist-first-v69-occupied-holdout-result`; the frozen
interpretation contract remains v6.8.

## Objective

Prove one narrow end-to-end bridge in which:

1. the existing trusted Reception One product-context service performs
   practice-scoped reads against an exactly owned disposable authored-synthetic
   PostgreSQL fixture;
2. it constructs the existing typed
   `reception.one.bureau.plan-input.v1` frame with opaque request-scoped
   handles, source labels, a context revision, `observed_at` and `expires_at`;
3. only the frozen v6.8 turn packet and minimal desk context enter the isolated
   model cell;
4. the deterministic proofreader reuses the same complete backend-held frame
   and freshness binding; and
5. any admitted output remains a proposal candidate requiring human review.

## Frozen boundaries

- data: newly created authored-synthetic fixture only;
- database owner: trusted backend only;
- cell database and product access: none;
- identity inside cell: no cloud, database, patient or service-account
  credential;
- context: exact matched patient, practitioner and selected appointment only
  in the model-visible desk context; no full Diary or unselected appointment
  payload;
- identifiers: opaque request-scoped handles only; raw database UUIDs remain
  in the trusted adapter map and are never serialized to the cell;
- effect: `proposal_only`;
- confirmation and appointment write authority: false;
- provider: the exact existing `gemini-2.5-flash` Bernie keyless-ADC Sydney
  lane only, after all provider-free gates pass;
- fallback, provider tools, grounding, retrieval and cache creation: false;
- occupied ceiling: one primary call plus one terminal proofreader correction,
  USD 1 maximum.

## Acceptance

The provider-free gate must prove:

- exact disposable database ownership and cleanup;
- practice-scoped read construction through
  `build_product_context_frame`;
- unchanged appointment, audit, idempotency and committed-event truth;
- the frozen v6.8 system instruction and schemas;
- exact model-visible field allowlist;
- no raw database identifier in the turn packet;
- source-labelled current Diary, staff dialogue, selected appointment and
  freshness evidence;
- same turn/task/context hashes for model and proofreader;
- deterministic oracle admission and proposal-only release;
- no provider or credential access.

The occupied gate may then run one authored-synthetic resize request. A second
call is permitted only for the frozen deterministic proofreader correction.
Every ledger must be consumed and all owned containers, networks, images,
processes and disposable database state removed.

## Explicit exclusions

Real, product-derived, patient, health, clinical or historical data; full
Diary exposure; product delivery; confirmation; mutation; production; Word;
voice; representative sessions; deployment and release remain closed.
