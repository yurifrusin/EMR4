## Fail-closed method

1. Bind every repository and pinned-package input by exact SHA-256 and bind all Git sources by full 40-character object ID.
2. Parse the failed sentinel author as Python AST; do not execute or import it.
3. Require exactly one `sentinel_source` function and exactly one returned bytes literal.
4. Apply a small deterministic JavaScript lexical-state scan to the generated bytes. The scanner identifies literal CR/LF control bytes inside a regular-expression literal or quoted string. It does not invoke Node, the Harness, a JavaScript parser, a broker, a worker, a model, a provider or the network.
5. Require the source spelling, Python AST value and generated-byte coordinate to form one unambiguous transformation chain. Bind the rc.7 relative-import branch and the consumed terminal's zero-HMR/exit-one facts, without using the raw stderr digest as an error-message oracle.
6. Compare only with the accepted passing sentinel control: the control must have no lexical violation and its accepted terminal must contain the first two ordered HMR events.
7. Accept `unique_supported_coordinate` only when exactly one first fatal lexical coordinate exists. Multiple or absent coordinates, binding drift, an invalid control, or any need for raw error reconstruction returns `insufficient_source_coordinate`.
