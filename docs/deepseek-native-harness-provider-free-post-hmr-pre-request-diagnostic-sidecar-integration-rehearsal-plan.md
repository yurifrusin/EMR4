- add exactly one relative import of `writePostHmrDiagnostic`;

fallback. The future runner must retain the accepted tool gates, one follow-up,

## Controller and broker-zero join

The broker reading has exact keys, one schema version, the same operation,
attempt and full 40-character candidate identity, five non-negative integer
counters (`request_count`, `provider_call_started`,
`provider_call_completed`, `provider_call_failed`, `request_rejected`) and a
fixed false raw-retention declaration. It is canonical JSON inside the exact
disposable root.

The controller reads both files independently. It may return
`post_hmr_pre_request_failure` only when the sidecar is canonical and
identity-matched and every broker counter is zero. A valid sidecar with any
non-zero broker counter becomes `post_hmr_request_boundary_unresolved`; an
absent or invalid sidecar retains `native_harness_terminal_failure`. Invalid or
mismatched broker evidence rejects the join. No model or prose selects any
coordinate.
