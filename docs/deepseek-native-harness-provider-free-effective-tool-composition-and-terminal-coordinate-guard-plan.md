## Frozen composition algorithm

The generated rc.7 setup helper must implement this exact order:

1. validate the preset id and sorted allowlist against constants;
2. await `agentCtx.agentPresets.mount(agentCtx, presetId)`;
3. read the exact scope key with `scopeOf(agentCtx)` and reject an absent key;
4. read `agentCtx.tools.view(scope)` once before restriction;
5. reject when `knownNames - restrictableNames` is non-empty, proving the guard
   is the first tool-composition action and no selected or unselected tool was
   registered into the child's own layer;
6. reject when any selected name is absent from `restrictableNames`;
7. install exactly one `agentCtx.tools.restrict({allow: selectedTools})`;
8. read `agentCtx.tools.schemas(scope)`, sort their names and require exact
   equality with `edit`, `glob`, `read`; and
9. return only the preset id, sorted effective names, count and a success
   coordinate.

No exception text, stack or dynamic package error is returned. The caller may
retain only the closed coordinate and the sorted safe tool-name projection.
The helper must never call `restrict()` after a failed inherited-name proof and
must never use a scope-local name as a restriction operand.

The exact failure vocabulary is:

- `EFFECTIVE_TOOL_COMPOSITION_INPUT_INVALID`;
- `EFFECTIVE_TOOL_COMPOSITION_PRESET_MOUNT_FAILED`;
- `EFFECTIVE_TOOL_COMPOSITION_SCOPE_MISSING`;
- `EFFECTIVE_TOOL_COMPOSITION_SCOPE_LOCAL_TOOL_PRESENT`;
- `EFFECTIVE_TOOL_COMPOSITION_EXPECTED_TOOL_NOT_INHERITED`;
- `EFFECTIVE_TOOL_COMPOSITION_RESTRICTION_FAILED`;
- `EFFECTIVE_TOOL_COMPOSITION_SCHEMA_VIEW_INVALID`;
- `EFFECTIVE_TOOL_COMPOSITION_EFFECTIVE_VIEW_MISMATCH`; and
- `EFFECTIVE_TOOL_COMPOSITION_UNCLASSIFIED`.

Success is `EFFECTIVE_TOOL_COMPOSITION_PASSED`. Coordinates are stable ASCII
constants; optional detail is a sorted comma-separated list matching
`[a-z_]+(?:,[a-z_]+)*` and may name tools only. Generic
`CUSTOM_RUNNER_FAILURE`, raw error messages and stack traces are forbidden.
