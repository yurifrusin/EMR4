## Controller-terminal assembly

The assembler consumes only the exact materialised bundle, canonical sidecar
and canonical broker reading through the accepted controller. It may create
one terminal with exact keys and one of the three accepted coordinates:

- exact sidecar plus all broker counters zero ->
  `post_hmr_pre_request_failure`;
- exact sidecar plus any non-zero broker counter ->
  `post_hmr_request_boundary_unresolved`; or
- absent/invalid sidecar plus valid broker reading ->
  `native_harness_terminal_failure`.

Invalid bundle or broker evidence rejects assembly. The terminal carries only
closed stage/cause/error coordinates, boolean readings, exact source hashes and
fixed false raw-retention/execution flags. It contains no dynamic error text,
stack, code, cause, path, prompt, response, session or credential.
