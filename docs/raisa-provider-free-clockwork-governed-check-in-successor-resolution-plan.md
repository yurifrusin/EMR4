## Frozen generic-tick design

1. A versioned generic intent contains only semantic inputs: one validated transactional closeout manifest, one bounded command manifest, one Baton acceptance label/path list and the next operation's explicit protected boundaries.
2. Caller-authored object IDs, revisions, counts, digests, transaction/generation/lease IDs, status fields, peer links, output paths and projection bindings are rejected recursively.
3. The clockwork reads the current live pointer and generation, validates zero canonical drift, resolves `HEAD` to a full 40-character commit, validates protected refs and requires all current canonical and clockwork metadata bytes to equal that clean Git source.
4. The currently selected live generation becomes the immutable predecessor. Its canonical bytes, metadata bytes, pointer identity and bundle digest are bound to the exact source commit before reduction.
5. The shared transactional reducer derives the next Continuity node, Compass position and latch. The generic tick replaces inherited protected boundaries only from the validated intent, then revalidates and rehashes the complete bundle.
6. The Baton result, next operation, clockwork relation and acceptance row are rendered deterministically from the validated manifest and acceptance input. The physical working-copy newline form is never an input; the renderer starts from the exact Git blob.
7. Canonical and metadata files are staged to same-directory temporary files, reread, and replaced under one exclusive clockwork lease. `current.json` is the final commit point.
8. Every failure before the pointer replacement restores and rereads the exact prior canonical files, metadata files and pointer. An injected failure after pointer replacement is a committed tick and must validate as such.
9. Idempotent replay of the same intent/source returns the selected generation without another publication or lease increment. A stale prepared tick, wrong writer, wrong source, abbreviated object, unsafe path, changed predecessor, active lease or canonical drift fails before publication.
10. Rollback restores the predecessor's canonical and metadata bytes from the bound full Git source, advances the pointer lease sequence, retains clockwork ownership and validates the restored live generation. Historical direct writers remain retired.
