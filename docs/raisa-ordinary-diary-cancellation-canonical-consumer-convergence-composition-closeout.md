## Outcome

The ordinary Diary now uses the same deterministic cancellation meaning as
Reception One. It requests only a dedicated delete proposal, checks that the
proposal binds the selected appointment and administrative reason, requires
visible staff confirmation, posts only to the canonical delete-confirm command
and admits only the strict minimal public receipt.

Every terminal or uncertain command outcome is followed by one fresh authorised
Diary read before a result is displayed. Current source truth defeats a
contradictory receipt, no optimistic local removal is treated as cancellation,
and a failed reconciliation leaves the editor visible with cancellation
disabled as `Refresh Required` rather than claiming success or non-commit.

The former 404-to-status semantic fallback, status-confirm idempotency path and
smoke-only optimistic cancellation are removed from this consumer. No backend,
OpenAPI, schema, migration or database source changed.

## API Spine finding

same REST/OpenAPI command kernel. Their presentation can differ, but the
proposal, confirmation, endpoint, receipt and fresh-truth obligations do not.
GraphQL remains read-only and no compatibility DELETE becomes authoritative.
