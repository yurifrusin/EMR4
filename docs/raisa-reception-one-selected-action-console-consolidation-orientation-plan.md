## Objective

Select the narrowest presentation architecture that prevents the four proven
selected-appointment actions from becoming four permanently stacked pieces of
middleware. Preserve the distinct status, time, duration and practitioner
truth and command contracts before another field is added.

This is an architecture-orientation tranche only. It may inspect repository
source and authored acceptance artifacts and produce repository-local plans,
contracts and evidence. It may not edit Diary product source, execute a
command, read product data or open a provider.

## Current evidence

At the task baseline:

- `meta-grid.js` retains four independent action-state objects and four
  field-specific executors;
- all four full-width action panels render sequentially for one selected
  appointment;
- each panel carries its own input, review button and polite live region;
- four-way busy, interruption and fresh-reconciliation behavior already
  converges safely;
- status delegates through the existing status proposal/confirm family; and
- time, duration and practitioner delegate through their field-specific
  bridges to the existing update proposal/confirm family.

The accepted closeouts prove each action independently. They do not require
all four editors to remain visible simultaneously.

## Options to decide

1. Keep four always-visible panels.
2. Use a single action dropdown.
3. Use free-text or model-interpreted intent as the sole action entry.
4. Use modal or drawer editors.
5. Use a compact deterministic action palette with one progressively
   disclosed existing field editor.

The decision must be based on discoverability, keyboard and screen-reader
behavior, small-screen density, provisional-versus-current truth clarity,
interruption, command convergence and future field accretion.

## Frozen acceptance

The tranche passes only if it:

1. selects one pattern and explicitly rejects the alternatives;
2. maps every visible action to its unchanged current bridge and command
   family;
3. freezes initial, switch, busy, interruption, terminal, focus and
   appointment-leaves-scope behavior;
4. proves that the selected pattern admits at most one visible field editor
   and no concealed provisional draft;
5. preserves one action-specific polite live region and the current
   confirmation dialog's focus and Escape ownership;
6. makes any future language intent capable only of opening an editor, never
   proposing or confirming a command;
7. freezes the narrowest next implementation surface and its test matrix;
8. records actual DeepSeek, Gemini and native-subagent efficacy; and
9. passes typed-contract, documentation, handover, Ruff and whitespace checks
   plus one fresh read-only Gemini veto at an unchanged clean candidate.
