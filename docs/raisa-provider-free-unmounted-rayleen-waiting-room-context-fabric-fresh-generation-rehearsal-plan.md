## Objective

Prove the next exact lifecycle step after the accepted inert Rayleen
invalidation/reassembly handoff. Trusted code must reconstruct the accepted old
generation and requirement, perform a deterministic fresh-authority check,
consume newly authored synthetic completed-read-shaped Diary and waiting-room
inputs for every affected dependency, rerun the accepted waiting-room adapter,
Current assembler and same-packet proofreader, admit one distinct newer frame
set and reject an older asynchronous result from superseding it.

## Deterministic lifecycle

1. Reconstruct and proofread the accepted invalidation/reassembly packet. Do
   not trust a supplied packet or reuse its event as replacement truth.
2. Verify the inert instruction is current and fixes every execution, source-
   read, returned-data, command and provider flag to false. Its ordered labels
   become obligations, not callbacks or authority.
3. Build a distinct generation request with a new need id and request revision
   greater than the superseded requirement. Revalidate the accepted authority
   binding at the new instant and derive a new need/grant through the accepted
   deterministic policy. The grant must be equal or narrower in every
   principal, role, practice, session, Bureau, purpose, source, field, location,
   time, item, byte, freshness and authority dimension.
4. Author a second synthetic completed Diary envelope and second synthetic A4
   waiting-room frame independently of the invalidation signal. Both must have
   later source revisions/observations and preserve exact practice, location,
   session and appointment coherence. Event metadata supplies no data fields.
5. Derive a fresh request-scoped alias manifest, run the accepted adapter and
   call its sole extractor with the authoritative new frame, binding, new grant
   and alias manifest. Only the extractor-recomputed deep copy is eligible.
6. Require exact refresh coverage for every dependency in the old requirement.
   The accepted signal currently affects both Diary and waiting-room frames;
   refreshing only the waiting-room frame must fail.
7. Carry forward only directory/private-session sources that the requirement
   did not name and that remain exact, granted, coherent and unexpired at the
   new assembly instant. Any affected, expired or changed carried source fails.
8. Assemble the new Current weave and rerun its unchanged same-packet
   proofreader. Require `RELEASE`, a distinct need/frame-set id and digest, and
   exact source-trace linkage.
9. Derive the new manifest and lease from that exact released frame set. Mark
   the new lifecycle generation `CURRENT` only inside the rehearsal packet;
   mount no watcher and persist no checkpoint.
10. The admission gate reconstructs every upstream value, proves the new
    request is still current, proves the old frame remains retired, and admits
    only the trusted new deep copy.
11. Run the accepted stale-result assessor for the older request coordinate and
    require `REJECT_SUPERSEDED_REQUEST`. Prove both completion orders: old then
    new still ends on the new generation, and new then old cannot roll back.
12. The final proofreader reconstructs the complete packet from authoritative
    inputs, verifies canonical equality and expiry/authority ceilings, then
    releases or blocks atomically.
