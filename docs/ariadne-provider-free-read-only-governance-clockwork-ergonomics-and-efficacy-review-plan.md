## Questions

The review will answer:

1. Which failures were safely contained, and at which stage?
2. Which failures required a rerun, publication or rollback despite being
   derivable from existing repository state?
3. Which operator-authored fields duplicate Git, schema, vocabulary, test,
   timestamp, transaction or publication facts?
4. Did the native-Harness gear coupling improve attribution, useful completion,
   or both?
5. Which single change removes the most measured operator work without
   weakening protected boundaries or adding a new approval gate?

## Measurement method

- Recompute graph counts from the canonical Continuity graph.
- Parse the four accepted efficacy readings and sum only identically labelled
  disclosed workflow lapses.
- Parse the two closeout intents and count bytes, lines and scalar leaves by a
  frozen recursive rule: mappings and arrays contribute the sum of their
  children; every non-container value contributes one leaf.
- Classify each recent lapse as one of:
  `derived_fact`, `closed_vocabulary`, `command_shape`,
  `prospective_projection`, `self_referential_accounting`, or
  `product_semantics`.
- Record whether containment occurred before provider I/O, before canonical
  mutation, after publication with byte-exact rollback, or only in ordinary
  product tests.
- Use commit timestamps only as bounded wall-clock proxies; do not infer human
  labor or model performance from elapsed time alone.

## No-added-bureaucracy acceptance rule

A proposed improvement is eligible only when all of these hold:

1. it makes at least one currently possible manual decision, duplicated field
   or rerun sequence impossible or unnecessary;
2. it introduces no net new required operator field, approval, named gate,
   provider call or closeout document;
3. it preserves full-Git binding, closed vocabularies, prospective protected
   boundaries, exact rollback and the single clockwork writer;
4. it reports all prospective errors in one pass where the existing state
   permits that computation;
5. it does not convert a safety invariant into free-form LLM prose; and
6. its future efficacy can be measured by fewer operator leaves, rejected
   preparations, postpublication rollbacks and elapsed closeout time while
   accepted development yield and safety remain non-decreasing.
